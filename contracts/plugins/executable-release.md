# Executable plugin release v1

A repository publishes one root manifest for each plugin version. Executable packages may contain a platform-specific Go driver, a static Web archive, or both. The package is a set of GitHub Release assets. Extracting an archive, installing a package and starting a driver are separate operations.

Authors can also sign a manifest-only release. Its attestation carries an empty `components` object and binds the raw manifest digest. Verifiers accept an empty inventory only when the pinned manifest declares no packaged components. Signing remains optional for legacy manifests.

## Storage connection form

A storage plugin can expose a standard host form using the manifest's JSON Schema. An executable package can bind its root `configSchema` annotation `"x-soha-test-connection-action": "storage.testConnection"` to the built-in connection test. A string field annotated `"x-soha-widget": "secret-ref"` stores a platform secret reference. A binding supplies resolved credentials only during an authorized driver call. See the [complete manifest fixture](../fixtures/json-schema/plugin-manifest/valid/executable-package.json).

## Detached signature

1. Build the assets first. Record the name, byte length and lowercase SHA-256 of the exact published bytes in the manifest. Commit the final manifest and point the release tag to that commit.
2. Generate `soha-plugin-attestation.json` according to the [release schema](plugin-release-attestation.schema.json). Bind the repository, the full commit SHA, plugin ID and version, digest of the raw manifest and the complete artifact inventory. Publish it and `soha-plugin-attestation.sig` with the same release. The signature is a 64-byte raw Ed25519 signature over **all original UTF-8 attestation bytes**, including any trailing newline. There is no JSON normalization, hashing prepass or embedded signing key.
3. Resolve the approved 32-byte Ed25519 public key from trusted source configuration or the administrator-confirmed repository binding. For first use, the author supplies the untrusted candidate key as the Release asset `soha-plugin-publisher.pem` (one PEM PUBLIC KEY block, DER SubjectPublicKeyInfo for Ed25519). Display the lowercase SHA-256 fingerprint of the raw 32-byte key. An untrusted candidate returns a read-only `publisher-trust-required` preview with the fingerprint, `signatureStatus: untrusted` and the same reserved preview-only marker. After explicit trust approval, obtain a fresh preview. A changed asset cannot override a preconfigured or previously trusted key. Verify the signature before interpreting the document. Reject duplicate JSON object members, unsupported fields or invalid schema. Compare the repository and commit with the resolved release, then the manifest digest, identity, version and exact component inventory with the pinned manifest. A valid signature for another commit or package is insufficient.
4. Verify byte lengths and digests of every required asset before committing an installation or upgrade. A platform driver must match the execution host. The Web asset is a gzip-compressed tar archive of relative POSIX paths, with a regular `index.html` at its root. Only directories and regular files are supported. Strip a single leading `./` and one trailing slash on a directory. Ignore a directory entry for the root itself. Reject empty, absolute or backslash paths, remaining empty, dot or dot-dot segments, links, special entries, file/directory conflicts and duplicate canonical paths. Apply extraction size and entry count limits before exposing any files.

A server may return `installEligibility: signed-release-required` when previewing a branch without a matching signed Release. In that response the required legacy string field `previewToken` contains the reserved literal `preview-only`. Install and upgrade reject that value. After the author publishes a matching signed Release, obtain a fresh preview and verify the publisher and artifacts. An untrusted key, invalid signature or failed upstream lookup is a separate error. Existing manifest-only installation keeps its original selection and confirmation semantics.
