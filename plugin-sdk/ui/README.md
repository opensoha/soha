# Soha plugin UI SDK

This ES module connects a static plugin page to the Web or Wails host through the browser's message channel. It has no runtime dependencies.

On the host, create a new iframe for each verified release and activation. Set `sandbox="allow-scripts"`. Use `const activation = preparePluginFrame(verifiedEntryURL)` and load `activation.url`. Serve the verified entry directly, without redirects. The activation secret lives in the entry URL fragment and must stay with the intended document. In its initial load handler call `attachPluginFrame({ frame, documentNonce: activation.documentNonce, pluginId, version, context, actions, getActiveVersion, invoke })`. The bridge binds the exact child window, opaque origin and a fresh channel nonce. A subsequent load closes this attachment. Dispose it explicitly when disabling, upgrading or unmounting the plugin. Supply the current active version through the synchronous getter. Route the allowed action to a server or desktop bridge that validates the user's current authorization, plugin identity, active version and action at execution. Honor the provided abort signal and return JSON (or null). Use `updateContext` to propagate new theme tokens or language.

In the plugin, call `connectPlugin({ pluginId, version, onContext })` using the release's identity. The first `onContext` indicates readiness. It receives `{ theme, locale, tokens }` at initialization and on changes. Call `await bridge.invokePluginAction(actionId, payload)` after initialization. `stale_version` asks the user to refresh the page. Dispose the bridge on teardown. An optional `parentOrigin` pins a known host origin. Otherwise the page learns it from the embedding parent at initialization. Each invocation has a bounded lifetime and a per-channel request number.

The host uses a wildcard window message to discover the opaque frame. The page transfers a new MessagePort back to its parent after checking the discovery message. The host accepts that port only from the intended frame and opaque origin with the matching activation secret and challenge. Theme data, actions and replies travel over the document-held port with the negotiated nonce. A newly navigated document cannot inherit the port. Timeouts and teardown signal cancellation to the host. Dispatch checks plugin identity, active version, allowed actions and request numbers. Authentication tokens and native handles belong to the host.
