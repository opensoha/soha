## Minimal rerun

From the Core repository, with installed `uv`, Python 3.13, PostgreSQL binaries and extensions (no existing database is used):

```sh
HQ_ENV_DIR=$(mktemp -d -t task123-hq-env)
uv venv --python 3.13 "$HQ_ENV_DIR/venv"
uv pip install --no-cache --python "$HQ_ENV_DIR/venv/bin/python" -r scripts/hindsight-qualification/requirements.lock
HQ_PG_BIN=/opt/homebrew/opt/postgresql@18/bin opensoha-verify run -- "$HQ_ENV_DIR/venv/bin/python" scripts/hindsight-qualification/run_local.py
# After the command exits and no consumer remains:
rm -rf "$HQ_ENV_DIR"
```

Use the workspace RTK prefix for shell execution. No extra tool cache is created. The runner allocates a temporary data directory under `OPENSOHA_VERIFY_DIR` and loopback ports, starts its own PostgreSQL process, real Hindsight API, and a local synthetic model endpoint, then stops those exact processes and removes its own data. It never switches Docker context or uses the default database URL. A port conflict fails the run; it never terminates the other listener. `qualify.py --base-url http://127.0.0.1:PORT` can target an already allocated disposable local service; it creates three random banks and deletes only those banks in `finally`. There are no automatic retain retries after ambiguous failure.

The assertions require synchronous retain completion, actual recall with original `document_id` and source revision metadata, no other bank's canary in any response, raw document deletion, empty raw recall after deletion, and preservation of the other two banks. The two projects of user A and user B use separate banks. This proves vendor namespace isolation; it does not prove Soha authorization or client-forged scope rejection. Model output is deliberately deterministic and embedding vectors synthetic. It does not evaluate Chinese extraction, semantic quality, real Gateway routing, budgets, latency, reflect, observations, or mental models.

## API and production gates

- The HTTP prefix is `/v1/default/banks/{bank_id}`; retain is `POST /memories`, recall `POST /memories/recall`, document delete `DELETE /documents/{document_id}`. `document_id` is the source identity, not a Soha user or authorization decision. The HTTP delete receipt is `success`, `document_id`, and `memory_units_deleted` (not the engine-internal `document_deleted`). The static schema still lists `/profile`; the fixed service actually returns 410 on that retired endpoint. The harness uses read-only `/config` to require a 404 before creating a bank. `metadata` values are strings.
- Async retain accepts a client UUID `operation_id`; replay returns the existing operation and conflicting operation types return 409. It is ignored for synchronous retain. Stable document identity alone must not be treated as cross-service exactly-once. The harness uses synchronous retain without retries.
- Recall source fields are nullable. Observations use `source_fact_ids`; `include.source_facts` may be truncated and reports `source_facts_truncated`. Missing provenance must fail closed before any model input, not be interpreted as authorization.
- Default `tags_match=any` and `all` include untagged data. Tags are not an ACL. Do not mix security scopes in one bank; use server-owned opaque bank mapping and current ACL/source revision checks.
- The fixed engine's `delete_document` invalidates observations referencing the deleted raw facts. This does not establish deletion of all mental models, historical summaries, caches, backups or late worker writes. `HINDSIGHT_API_LLM_TRACE_DELETE_WITH_DOCUMENT` defaults to **false**; even opt-in trace deletion documents possible late worker calls requiring retention sweeps. Soha needs tombstones/fences, tracked propagation and safe context rebuild. Keep reflect/automatic consolidation/mental models disabled until their source and deletion guarantees pass dedicated acceptance; do not claim V10 from raw recall deletion.
- Migrations bootstrap vector extensions in `public` and manage schema/index changes. Use a separate database/role, not Core's schema or a shared business DB. The local role is a throwaway superuser inside a private loopback-only cluster; this is not a production privilege recommendation.
- Gateway must support the fixed retain/reflect/consolidation structured-output OpenAI-compatible calls, embeddings with the exact configured dimension, optional reranking provider protocol, usage/missing-usage handling, and background operations. Explicitly configure every per-operation override or prevent it from bypassing the main Gateway. The harness sets OpenAI embeddings and `rrf` passthrough reranking, disables auto-consolidation and offline model downloads. Production egress deny rules and capture must demonstrate no direct provider/model downloads. No real Gateway credentials are read here.

## Real Gateway preflight

`opensoha-verify run -- python3 scripts/hindsight-qualification/gateway_preflight.py` defaults to a read-only enabled-route inventory. It uses the supported `soha token list --profile local` refresh flow, capturing all CLI output; the management JWT stays in memory and is never sent as a relay identity. Destinations must be loopback HTTP, proxies are disabled and redirects rejected.

`--invoke` explicitly creates one unique 15-minute PAT through the normal API: `ai.gateway.relay.invoke`, `llm-relay`, purpose `llm-relay`, OpenAI only, and the requested enabled model only (default `gpt-6-luna`). It makes one non-streaming strict JSON-schema extraction request with synthetic Chinese input and `max_completion_tokens=160`; it never retries paid inference or uncertain credential creation. `--embedding-only --invoke --embedding-model NAME` performs intent2 with one normal PAT/models GET and one embedding request, without repeating chat. `--discover-upstreams` additionally uses normal management API upstream list/test discovery (which records its usual audit), selecting active/explicitly enabled OpenAI upstreams; no provider credentials are read. The small fact schema is a protocol probe, not an execution of the Hindsight extraction engine. The PAT value is neither printed nor written to disk. When the creation receipt supplies a token ID, `finally` first attempts exactly one revoke for that ID, then independently lists tokens to verify `revokedAt`; a failed list cannot prevent the revoke. Only a lost creation receipt without an ID requires unique-name reconciliation before that one revoke. A lost revoke receipt is resolved by listing, without replaying revoke; missing confirmation leaves `cleanup_requires_followup=true`. Reports contain only non-secret token identity, bounded outcome categories and numeric token usage. `cleanup_requires_followup=true` means the caller must reconcile the reported action/name before another credential action.

`--action-key KEY` (or the `run(..., action_key=KEY)` argument) records the trusted caller's assigned action identity; omitted values retain the original intent1/intent2 defaults. Supplying an identity does not authorize another external action. Historical intent3 evidence retains both the wrapper-assigned key3 and the previous script's static key2. The cleanup/action-identity fix has offline coverage only; the three historical real PAT receipts are preserved and no real qualification was repeated for this fix.

No embedding model is guessed. `--embedding-model NAME` is allowed only when that exact enabled OpenAI route is present; an absent route fails before credential creation. Omitting it sends zero embedding requests. Exit 0 means inventory completed or the selected protocol probes passed; `PREFLIGHT_PASS` does not mean full Hindsight qualification. The report always leaves full Hindsight and derived deletion as `NOT_RUN`.

Offline guard/lifecycle regression:

```sh

```

## Real Hindsight + Gateway lifecycle runner

`run_gateway.py` restores no service defaults and touches no existing database. Run it with the fixed lock environment above. It starts its own PostgreSQL cluster and real slim API on loopback dynamic ports, verifies the actual extensions, then creates the registered H1 attempt's single restricted 30-minute relay PAT. `--prepare-only` checks API/database startup with no PAT or model calls. `--attempt Axx` records the caller-registered action identity; it is not authorization for another paid attempt.

```sh
opensoha-verify run -- "$HQ_ENV_DIR/venv/bin/python" scripts/hindsight-qualification/run_gateway.py \
  --attempt A05 --core-check --manual-models --production-guard --chat-limit 16 --embedding-limit 48 \
  --evidence ../docs/tasks/123-dsh-hindsight-unification/evidence/hindsight-real-gateway.json
```

The parent alone holds the real PAT. Hindsight receives a random local capability and separate `/chat/v1` and `/embed/v1` proxy URLs. The proxy accepts only the selected chat/embedding model on its matching provider endpoint, defaults to 12 chat / 30 embedding / 600 seconds. The registered A04 manual-model qualification may raise the total to 16 chat / 48 embedding; non-manual lifecycle/Core calls remain capped at 12/30, so the extra allowance cannot fund unrelated operations. It caps generation at 2048 tokens, and verifies embedding input remains string/list-of-strings and the result contains 1024 finite nonzero dimensions. It transparently verifies `encoding_format=float` and text inputs without rewriting them. The official `HINDSIGHT_API_EMBEDDINGS_OPENAI_EXTRA_BODY={"encoding_format":"float"}` setting controls the actual Hindsight/OpenAI SDK wire format; an offline native-SDK HTTP test verifies this path. Remote trace collection and vendor LLM trace persistence are disabled; model/Gateway credentials and raw upstream errors are never logged. HTTP proxy settings reject other configured HTTP egress and Hugging Face is offline; this is not an OS-level production egress proof.

The isolated retain chunk size is 1024, below the 2048 completion budget as required by Hindsight's own configuration validation; each synthetic source fits entirely in a chunk. Startup's optional `Say ok` connectivity probe is disabled so credentials are created only after health readiness; actual retain/consolidation/recall requests still use the real models and all scenario assertions. A01–A06 disabled vendor LLM retries. A07 sets official global/retain/consolidation LLM `max_retries=1`, with reflect inheriting the global value; embedding and worker retries remain disabled. The fixed provider keeps its OpenAI SDK retries at zero and owns this one retry itself. It retries 400/429 and JSON parse errors as well as 502/connection errors; 401/403 fail immediately. All schema/fact assertions remain intact, every forwarded attempt consumes the hard proxy budget, and a rejected budget cannot forward another request. This recovers only the pure LLM request before its complete JSON is returned; an ambiguous retain/operation or entire scenario is not resubmitted. The worker/API and all bounded proxy requests converge before PAT revocation. A lost create receipt is reconciled by exact unique name, never replayed; a known token ID is revoked once and confirmed by independent listing.

The qualification-only chat proxy sends one Gateway SSE request per Hindsight non-streaming request and reconstructs the native completion. It preserves content, fragmented/parallel tool calls, refusal, finish reasons and exact usage; `[DONE]`, every terminal choice and valid usage are required. Error frames, truncation and bounds fail closed. This adapts the currently deployed Gateway's 30-second non-streaming first-byte timeout without changing its configuration, bypassing authentication or retrying. It is not evidence that a production Gateway timeout fix was deployed.

With `--core-check`, the parent compiles and executes `TestClientRealHindsightLifecycle` inside the same verification lock using its own temporary modfile and sibling contracts source. With `--production-guard`, the actual production capability gateway is imported on its own dynamic loopback port, with an in-memory local service cap and the native API as its fixed test upstream. Core business requests use that guard; only the owner's exact bank cleanup uses the native API. The actual Core client/BackendService calls the real API/private PostgreSQL; the Core memory/outbox store and source permission validator remain explicit fixtures. The Core test owns a separate UUID bank and deletes it. Its result is recorded independently: failure keeps the overall result failed, while vendor scenarios may still run after exact Core bank cleanup is confirmed. Unknown cleanup, changed inputs, or budget/safety failures stop the run. The binary runs in its package directory, matching `go test` source-hash lookup semantics.

`qualify(..., full=True)` adds real consolidation with complete observation source-fact provenance, source/derived observation deletion, correction to a new document revision, and a model barrier that holds an asynchronous retain while its source is deleted. Reappearance is recorded as `UNSAFE_REAPPEARED`, never converted to a deletion PASS; product tombstones/fences and mental-model/trace/backup deletion remain separate requirements. `--manual-models` additionally creates a real grounded model, completes a second generated version with fact-bearing history, then pauses a full refresh while the source/model are deleted. It records the exact content/provenance/stale/history fields after source deletion, captures native deletion residue, then routes the same document DELETE (already absent) through the production guard to trigger its internal model purge, checking model/history visibility and exact private PostgreSQL row counts, and checks that the in-flight refresh cannot recreate either. The corrected document also exercises a guarded successful raw DELETE without another model generation. Native-vendor residual behavior and the production guard's protection remain distinct results. Barrier expiry is a failed proof, never a deletion PASS. Original fixture qualification remains the default and its historical evidence is preserved. Each actual run appends its exact inputs, failures, model counts, Core events and resource receipts to the task evidence JSON; a partial vendor result is not full product acceptance.

The observation check also follows actual source-unit IDs to their stored observations and reads scoped PostgreSQL history/canary row counts before and after deletion. An initially empty or non-fact-bearing history is `NOT_PROVEN_HISTORY`, even when the post-delete count is zero; no historical rows are inserted to manufacture proof.
